# HYPE FORM / Visual FX Lab v28.2.36 — QA

Date: 2026-09-21

v28.2.36 addresses two Mac observations from v28.2.35: Native FFmpeg did not feel materially faster, and export appeared to stall when the HYPE FORM browser tab was not active.

Only two protected export functions were deliberately revised: `waitForVideoSeek()` and `waitForExactVideoFrame()`. Offline export now treats the completed `seeked` event as the decode barrier and does not add a second `requestVideoFrameCallback()` wait. Preview/scrubbing keeps rVFC confirmation.

Native throughput changes:
- one native frame upload is pipelined while the next frame is rendered;
- strict frame ordering remains enforced by the helper;
- hidden-document export no longer relies on `setTimeout(0)` yielding;
- the Mac helper launches a dedicated Chrome app window with background timer/renderer/occlusion throttling disabled.

Profiler now separates FX Render / Seek / Readback / Pipe Wait / Finalize and reports FFmpeg pipe time.

Validation:
- JavaScript syntax: PASS
- Python syntax: PASS
- Export contract: PASS, 13 functions with 2 intentionally updated hashes
- Native export contract: PASS, 17 checks
- Static release audit: PASS, 217 unique DOM IDs / 315 unique functions / 53 FX
- Raw RGBA → helper → FFmpeg H.264: PASS
- 90 frames / 30 fps / 3.000 sec output: PASS

The validation host is Linux, so Apple VideoToolbox throughput and macOS Chrome occlusion behavior require confirmation on the target Mac.
